The Problem

SRE at a Major Bank — A Broken Process

"Every P1 starts the same way. Someone pages me at 2am, I join the bridge call, and the next two hours are everyone saying their component is fine. By the time we find the root cause, the customer damage is done."
— Senior SRE · Core Banking Platform

The Siloed Teams Problem

  • App team says app is OK
  • DB team says DB is OK
  • Platform team says OCP is OK
  • Infra team says hardware is OK
  • Nobody owns the cross-layer failure

Bridge Call Reality

  • 30–40 people on a call
  • 2–4 hours to identify root cause
  • RCA doc written days later from memory
  • Same failure pattern recurs next quarter

The Real Challenge

The failure lives at the intersection of four domains — APM traces, platform events, infrastructure metrics, and application logs. No single monitoring tool sees across all layers simultaneously.

  • Instana sees app symptoms — not the infra cause
  • OpenShift sees pod failures — not why MySQL is slow
  • Infra team sees NIC errors — not the business impact
The Solution — IBM Bob + OpenShift

Agentic SRE — Replace the Bridge Call

IBM Bob runs as parallel headless pods on OpenShift. Each pod is a specialised AI agent assigned a single data domain. They investigate simultaneously — then a final agent cross-correlates all findings into one RCA report and an Ansible remediation playbook.

①
Trigger — A single POST request launches all agents simultaneously via OpenShift Jobs
②
Parallel investigation — 4 Bob agents query Instana APM, OpenShift platform, and infrastructure telemetry concurrently, writing JSON findings to a shared PVC
③
Aggregation — A 5th Bob agent reads all 4 findings, cross-correlates signals across domains, and produces a complete RCA + Ansible playbook
④
Remediation — The generated playbook targets the specific root-cause service with evidence-grounded fixes — not a generic template

Bob's Role in Each Pod

Bob is IBM's AI engineering assistant. Each pod is given a custom mode (a role definition) and a prompt. It autonomously uses tools — execute_command, read_file, write_file — to investigate and write structured findings. No human in the loop.

What Changes

  • 2–4 hours → <5 minutes to root cause
  • Cross-domain correlation no single tool provides
  • Structured, auditable RCA before the bridge call starts
  • Automated Ansible remediation — not just a diagnosis
  • Runs 24×7 — no on-call engineer required to start

The Four Agent Domains

  • Instana Query — all open events & incidents
  • Instana RCA — P95 latency, traces, error rates
  • OpenShift Check — pods, nodes, operators, events
  • Infra Check — CPU, disk, NIC, storage telemetry
